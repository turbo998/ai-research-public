Across all 544 formal jobs, 537 were schema-valid and 456 were machine-accepted; all 8 E2E paired bootstrap checks are `inconclusive`. Support routing degraded acceptance vs Strong-only (-25.0 pp for Decision-1, -68.8 pp for Strands/Mini); RAG reached 16/16 on Rule, Mini, Sol, and Strands, but 4 template clusters (8 base cases) cannot prove <=2% non-inferiority.
Why the `✕` misses happened: calibration abstention, ZH JSON drift, and unsafe uncalibrated booleans. Mini-label had 1/8 false allow on unsafe gating; Mini-prob had 5/8 ZH scoring schema/mean failures; Strands 2B had high ordinal spread on 5-level scoring (MAE 0.7412) and abstained on all 16 support tickets.

UNDER THE HOOD

One `/v1/systemone` contract, two confidence math worlds

Both Microsoft-Decision-1 and Strands Decider consume the same structured `state + questions` payload and score `<answer>` in a single forward pass—but their Score confidence formulas and verifiers differ.

{
  "model": "Microsoft-Decision-1 | StrandsAgents/strands-decider-2B-qwen3.5-v1-2610",
  "state": "{\"language\":\"en\",\"request\":\"Recover access after changing email...\"}",
  "questions": {
    "department": { "type": "choice", "criteria": { "billing": "...", "account": "..." } },
    "sufficient": { "type": "noul",   "instructions": "Are facts sufficient to answer safely?" },
    "relevance":  { "type": "score",  "criteria": { "0": "Irrelevant", "4": "Exact match" } }
  }
}

Score the passage relevance from 0 to 4.

0 - 0: Irrelevant · 1 - 1: Weak · 2 - 2: Partial · 3 - 3: Good · 4 - 4: Exact match

</question>

# Choice confidence (Jev & Strands): (N * p_max - 1) / (N - 1)
# Strands Score confidence (std-dev): clamp((sigma_max - sigma) / (sigma_max - sqrt(0.1)), 0, 1)
# Harness verifier: checks 4dp half-unit rounding bounds & per-attempt 5-min Entra bearer refresh
Zero generated output tokens for native deciders vs. full JSON token generation for LLM probability wrappers. Strands encodes `<state>` once via `_fork_layered_cache` (Gated DeltaNet conv/recurrent states + attention KV) and projects the `<answer>` hidden state (`pointer_dim=768` in v1 soup) against each option's final token.

MY TAKE

Where native decision models fit, and where they do not

Engineering guidance synthesized from 544 formal test rows, 1,179 live model calls, and three concrete routing architectures (TypeSafe Jev, Azure Decision-1, local Strands Decider).

✅ Good fit
  • Sub-second closed-set rubric scoring & relevance grading (Decision-1: 16/16, MAE 0.0082, ECE 0.0149 at 701 ms)
  • Calibrated probability gating with explicit abstention (Decision-1: 15/16, 0/8 false allow, Brier 0.0051 at 636 ms)
  • High-volume tool/intent classification where $0.042/1M input & 0 output tokens beat LLM JSON wrappers
  • Multi-question shared-prefix fanout over a single state payload (`/v1/systemone`)
  • GPU/MPS-backed edge deployment of Apache-2.0 Strands Decider when data cannot leave local infrastructure
⛔ Not for
  • Replacing deterministic authorization, ownership, tool allowlists, or refund/money policy checks
  • Claiming E2E multi-model routing cost/speed wins when the small generator fails task acceptance (Support 2/16)
  • Running 2B Gated DeltaNet models on x64-emulated CPU for latency-sensitive online routing (6.3–33.0 s)
  • Treating uncalibrated LLM boolean labels (`Mini-label` 1/8 false allow) or ZH JSON probabilities as calibrated gates
  • Extrapolating 8-base-case pilot intervals (`status=inconclusive`) as population <=2% non-inferiority guarantees
Readiness & Provenance: `measured` 4-model pilot (544/544 formal rows; committed upper $1.666326800 / $50 cap; local Strands server stopped). Jev (`jev-1.13.0`) remains `untested_missing_external_api_key`.

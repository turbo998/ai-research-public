MY TAKE · AI SOLUTION ARCHITECT PLAYBOOK 7 / 7

架构师选型裁决：以 HVE 四层工件与 `/clear` 管治上层 SDLC，以 DSH 能力缝隙与 Claude SDK 驱动底层内核

没有任何单一框架能通吃所有层级——最顶尖的 AI Solution Architect 应当按照“上层规范与上下文隔离 + 下层微内核与异构子智能体联邦”构建企业级复合 Harness。

✅ 最佳适用场景 (Good Fit)

1. 采纳 DeepSeek DSH 微内核：
• 需要将工具无缝切换至远程 SSH、Docker 或云沙箱而不分叉工具代码（三角色能力缝隙）。
• 存在 20+ 步高频工具编排，需用 dsh-tool-executor-ptc (run_code) 消除中间 Token 污染。
• 需在一个父会话中联邦调度 Claude Code、Codex、ACP 与进程内 Fork 子智能体。

2. 采纳 Claude Code & Agent SDK：
• 快速在研发 CLI 或 CI 管线中嵌入成熟自主循环，并强制实施父子共享 max_budget_usd 成本硬顶。
• 挂载大量企业 MCP Server，依赖 ToolSearch 延迟加载与 readOnlyHint 并发加速。

3. 采纳 Microsoft HVE Core：
• 百人级研发组织推广标准化 SDLC（Research → Plan → Implement → Review），通过阶段间 /clear + .copilot-tracking/ 磁盘工件彻底消灭 200K 会话跳步，并用 Vally 套件做 CI 行为回归。

⛔ 不适用与反模式禁区 (Not For)

1. 切勿在单次 200K+ 会话中裸跑全流程开发：
• 不做阶段 /clear 或子智能体隔离，系统提示词权重必跌至 1.5%，模型将无视安全规范直接改代码。

2. 切勿在会话中途直接覆写 Node-0 系统提示词：
• 每轮拼接动态时间戳或目录树到首条 System Message 会导致 100K+ 前缀 KV Cache 100% 失效（应改用 DSH in-history 追加或 Claude CLAUDE.md 静态前缀缓存）。

3. 切勿在同一 Agent 混用 Native 与 PTC 工具表面：
• DSH PTC 模式下非 run_code 直接调用将返回 UNKNOWN_TOOL；且中间大对象受限于 Worker 内存。

4. 切勿为 3 步轻量脚本硬套分布式 Team DAG（S11 ✕）：
• 简单脚本直接用 dsh-sdk-minimal 或单次 query()。
